# Web版RSS阅读平台功能规格说明书

> ⚠️ **本目录是设计阶段的原始文档，不是当前实现的说明。**
>
> 这份规格写于项目动工之前，描述的是当时设想的方案。实现过程中做了
> 几处方向性调整，因此下面这些内容**已经过时**：
>
> - 数据库：文档写 PostgreSQL / Supabase，实际用的是 **SQLite**（Prisma + 单文件）
> - 部署：文档写 Vercel Serverless，实际主推 **Docker 自托管**（也有 standalone 直跑）

> - 手机注册：文档写「邮箱或手机号注册」，实际只做了邮箱

## 1. 概述

### 1.1 项目背景
随着互联网信息碎片化加剧，用户需要高效的信息聚合工具。RSS作为成熟的信息聚合协议，能够帮助用户一站式获取各类平台更新内容。当前市场上的RSS阅读工具存在体验参差不齐、订阅流程繁琐、缺乏内置优质源市场等问题。

### 1.2 项目目标
开发一款PC端Web版RSS阅读平台，聚焦：
- 优质阅读体验
- 便捷订阅功能
- 内置RSS市场（含GitHub、微信公众号源）
- 用户注册登录与个人中心管理

### 1.3 目标用户
- 信息工作者：需要高效获取行业资讯
- 开发者：关注GitHub项目动态
- 内容消费者：订阅博客、公众号等内容源

## 2. 功能需求

### 2.1 用户管理模块

#### 2.1.1 用户注册
**用户故事**：作为新用户，我希望通过邮箱或手机号注册账号，以便使用平台的个性化功能。

**验收标准**：
- [ ] 支持邮箱注册（邮箱+密码+验证码）
- [ ] 支持手机号注册（手机号+短信验证码+密码）
- [ ] 密码复杂度要求：8-20位，包含字母+数字
- [ ] 邮箱注册后需激活方可登录
- [ ] 注册时需勾选用户协议和隐私政策
- [ ] 手机号/邮箱唯一性校验
- [ ] 注册失败给出明确错误提示

#### 2.1.2 用户登录
**用户故事**：作为注册用户，我希望通过多种方式登录，以便快速访问我的订阅内容。

**验收标准**：
- [ ] 支持邮箱+密码登录
- [ ] 支持手机号+密码登录
- [ ] 支持"记住密码"功能（7天有效期）
- [ ] 支持忘记密码找回（邮箱/手机验证）
- [ ] 连续5次密码错误锁定账号15分钟
- [ ] 账号状态校验（未激活、禁用状态提示）

#### 2.1.3 个人中心
**用户故事**：作为登录用户，我希望管理个人资料和订阅，以便获得个性化体验。

**验收标准**：
- [ ] 查看/编辑个人资料（昵称、头像、简介）
- [ ] 修改密码功能
- [ ] 绑定/解绑手机号/邮箱
- [ ] 订阅管理入口
- [ ] 阅读历史查看与删除
- [ ] 收藏内容管理与搜索
- [ ] 账号注销功能（数据删除确认）
- [ ] 消息通知开关
- [ ] 登录日志查看

### 2.2 RSS订阅模块

#### 2.2.1 自定义RSS订阅
**用户故事**：作为用户，我希望通过RSS源URL订阅内容，以便获取感兴趣的更新。

**验收标准**：
- [ ] 顶部导航栏和个中心提供"添加订阅"入口
- [ ] 输入RSS源URL后可进行有效性验证
- [ ] 验证成功后自动抓取源名称、简介、图标
- [ ] 验证失败给出明确提示
- [ ] 订阅时可选择分组（已有或新建）
- [ ] 可设置是否接收更新通知
- [ ] 订阅成功后自动同步最新内容

#### 2.2.2 内置RSS市场
**用户故事**：作为用户，我希望从内置市场中发现优质RSS源，以便快速订阅感兴趣的内容。

**验收标准**：
- [ ] 首页显著位置设置"RSS市场"入口
- [ ] RSS源按分类展示（科技、资讯、GitHub、微信公众号、生活、财经等）
- [ ] GitHub项目和微信公众号作为重点分类突出展示
- [ ] 每个源展示图标、名称、简介、更新频率、订阅人数
- [ ] 支持按订阅人数、更新频率排序
- [ ] 支持关键词搜索（源名称、简介、分类）
- [ ] 点击"立即订阅"直接完成订阅（可选择分组）
- [ ] 无效源标记"不可订阅"并提示用户

#### 2.2.3 订阅管理
**用户故事**：作为用户，我希望管理我的订阅，以便保持订阅列表的整洁。

**验收标准**：
- [ ] 订阅列表按分组排列展示
- [ ] 支持新建、编辑、删除分组
- [ ] 删除分组时订阅源自动归为"未分组"
- [ ] 支持拖拽订阅源到不同分组
- [ ] 支持单个/批量取消订阅（需确认）
- [ ] 支持编辑订阅源（分组、通知设置）
- [ ] 支持按订阅时间、源名称、更新频率排序
- [ ] 新内容标记未读数量
- [ ] 支持消息通知提醒（需开启开关）

### 2.3 阅读模块

#### 2.3.1 阅读界面布局
**用户故事**：作为用户，我希望在舒适的界面中阅读内容，以便获得良好的阅读体验。

**验收标准**：
- [ ] 采用三栏布局：左侧订阅列表、中间内容列表、右侧阅读详情
- [ ] 适配PC端主流分辨率（最小1366×768）
- [ ] 支持手动调整三栏宽度（拖拽分隔线）
- [ ] 阅读区背景浅色（默认白色），字体清晰
- [ ] 顶部导航栏固定，滚动时不消失

#### 2.3.2 内容展示
**用户故事**：作为用户，我希望清晰地浏览和阅读RSS内容，以便获取信息。

**验收标准**：
- [ ] 内容列表按发布时间倒序排列
- [ ] 每条内容展示标题、发布时间、来源、摘要
- [ ] 未读内容标题加粗并标记"未读"
- [ ] 支持批量标记已读/未读
- [ ] 阅读区展示内容详情，保留原有排版和图片
- [ ] 支持字体大小调整（小、中、大、超大）
- [ ] 支持字体切换（微软雅黑、宋体、黑体）
- [ ] 支持主题切换（浅色、深色、护眼模式）
- [ ] 支持图片点击放大查看
- [ ] 支持链接点击跳转（新标签页打开）

#### 2.3.3 阅读操作
**用户故事**：作为用户，我希望在阅读时进行各种操作，以便管理我的阅读内容。

**验收标准**：
- [ ] 支持快捷键翻页（↑上一篇、↓下一篇）
- [ ] 支持收藏/取消收藏内容
- [ ] 支持分享内容（微信、QQ、复制链接）
- [ ] 支持按关键词搜索当前订阅源/分组内容
- [ ] 支持按发布时间过滤（近1天、3天、1周、1个月）
- [ ] 支持给内容添加自定义标签
- [ ] 标签可编辑、删除

#### 2.4.3 帮助中心
**用户故事**：作为新用户，我希望获得使用指南，以便快速上手平台。

## 3. 非功能需求

### 3.1 性能需求
- 首页加载时间 ≤ 2秒
- RSS市场页面加载时间 ≤ 3秒
- 阅读页面内容加载时间 ≤ 1秒
- 自定义订阅校验时间 ≤ 2秒
- 支持同时在线1000+用户
- 用户操作响应时间 ≤ 500ms
- 内置RSS源每30分钟同步一次
- 自定义订阅源每1小时同步一次

### 3.2 兼容性需求
- 支持Chrome、Edge、Firefox、Safari最新版本及前两个版本
- 最小适配1366×768分辨率
- 支持1920×1080、2560×1440等主流分辨率

### 3.3 安全性需求
- 用户密码采用加密存储（bcrypt）
- 个人信息加密传输（HTTPS）
- 支持登录密码、手机验证码双重验证（可选）
- 异常登录触发提醒
- 定期校验RSS源安全性，过滤恶意源
- 用户数据每日自动备份，保留30天
- 防SQL注入、XSS、CSRF攻击

### 3.4 易用性需求
- 核心功能操作步骤 ≤ 3步
- 所有操作给出明确提示
- 新用户无需查看帮助即可完成基础操作
- 阅读页面支持快捷键操作

### 3.5 可扩展性需求
- 架构支持后续新增功能
- RSS市场支持新增更多类型RSS源
- 预留第三方接口扩展

## 4. 界面需求

### 4.1 整体风格
- 简洁、清爽、极简风格
- 浅色主色调（白色背景、深灰色字体）
- 低饱和度辅助色（蓝色用于按钮、标记）
- 界面元素对齐整齐，间距均匀
- 字体清晰易读，无冗余装饰

### 4.2 核心页面
- **登录/注册页面**：表单居中，提示清晰，按钮突出
- **首页**：导航固定，展示常用订阅、热门源、最新更新
- **RSS市场**：左侧分类导航，右侧卡片式源列表
- **阅读页面**：三栏布局，左侧可折叠，阅读区宽敞
- **个人中心**：左侧功能导航，右侧内容展示

### 4.3 交互需求
- Hover效果：颜色加深、阴影变化
- 加载状态：简洁加载动画
- 弹窗提示：成功3秒自动关闭，失败需手动关闭
- 拖拽交互：分组拖拽排序、栏宽调整

## 5. 技术约束

### 5.1 部署架构
- 前端：Next.js 14 + TypeScript + Tailwind CSS
- 后端：Next.js API Routes + Serverless Functions
- 数据库：PostgreSQL (Supabase)
- 认证：NextAuth.js
- 部署：Vercel + GitHub
- RSS解析：rss-parser

### 5.2 合规性约束
- 内置RSS源需符合对应平台版权规范
- 不存储RSS源完整原文（仅缓存摘要）
- 查看原文跳转至原网站
